# SmartLading PRD：采购决策副驾驶（MVP）

Oct 28, 2026 · @Jason Wang

## 背景与目标

Commit MVP 要让一个中小品牌商在 5 分钟内，对一张采购单的 2–3 个备选订货量做出带风险量化的选择。

### 问题陈述

中小品牌商的每一张采购单都同时决定了库存和现金：订多了压死现金，订少了断货。关税变化和供应商风险会随时改变这笔下注的赔率。目前这些决策依赖 Excel 和直觉，运营和财务各算各的，无法在下单前看清最坏情况。

### 产品目标

- 把需求、交期、关税、供应商风险和现金流放进同一个模拟中，输出每个订货方案的现金跑道分布和断货概率
- 自动读取关税和供应商相关的文本信号，转成模型参数，减少手工更新
- 给出推荐方案和自然语言解释，让没有财务背景的老板也能理解权衡

### 非目标（MVP 不做）

- 不做完整的需求预测模型，使用历史分布即可
- 不做 ERP 或电商平台的实时数据接入
- 不做多仓库、多币种的复杂场景
- 不代替用户自动下单或付款

## 目标用户与场景

主要用户是自己拍板采购的品牌商老板或运营负责人；MVP 只服务这一类角色。

| 画像 | 描述 | 核心任务 | 当前做法 |
|---|---|---|---|
| 品牌商老板（主要） | 年销售额几百万到几千万美元，SKU 20–200 个，从中国、越南等地工厂采购，无专职 CFO | 决定每张采购单订多少、何时下、是否接受预付条件 | Excel 估算 + 经验判断 |
| 运营负责人（次要） | 负责补货和供应商沟通，需要向老板说明采购建议的理由 | 准备补货方案并说服老板 | 手工整理库存表和报价 |
| 财务人员（MVP 不服务） | 外包会计或兼职财务 | 事后对账、做现金预测 | 月度报表 |

### 关键场景

- **旺季备货**：黑五、圣诞前的大批量补货，订货量决定全年利润
- **关税变动**：政策公告后，判断是否提前囤货或调整产地
- **供应商条款**：工厂要求提高预付比例或最低订货量时，评估风险敞口

## 功能需求

共 6 个功能，F1–F4 为 P0，F5–F6 为 P1；每个功能列出验收标准。

### F1 业务状态模型（P0）

存储并展示品牌的当前状态：SKU、供应商、在途订单、库存、现金和授信。MVP 通过预置的虚构品牌数据加载，支持在界面中编辑关键字段。

- [ ] 加载一个包含 20 个 SKU、3 家供应商、现金和授信额度的虚构品牌
- [ ] 可编辑供应商的交期、最低订货量、预付比例和风险评分
- [ ] 任何字段修改后，模拟结果需重新计算

### F2 采购决策模拟器（P0）

用户选择一个 SKU 和供应商，输入 2–3 个订货量方案，系统运行蒙特卡洛模拟并并排展示结果。规格见"模拟引擎规格"。

- [ ] 支持 2–3 个方案并排比较
- [ ] 每个方案输出：现金跑道 P10/P50/P90、断货概率、预期利润、最坏情况（P5）损失
- [ ] 现金余额随时间的扇形图，标出现金安全线
- [ ] 相同输入和随机种子，结果完全一致

### F3 风险信号提取（P0）

用户粘贴或选择一条文本（关税公告、供应商新闻），LLM 提取结构化的参数变化，用户确认后写入状态模型。

- [ ] 输出包括：影响对象（HTS 编码、供应商或 SKU）、参数名称、变化值、发生概率、原文引用
- [ ] 引用必须是原文中的句子，界面中高亮显示
- [ ] 用户可以接受、修改或拒绝每一项变化
- [ ] 无法识别时明确提示"未发现可量化的影响"，而不是编造参数

### F4 建议与解释（P0）

基于模拟结果给出推荐方案，并由 LLM 生成解释。推荐逻辑由规则决定，LLM 只负责叙述。

- [ ] 推荐规则：在"现金跑道 P10 不低于安全线"的约束下，选择预期利润最高的方案；没有方案满足约束时，推荐风险最低的方案并给出警示
- [ ] 解释中引用的所有数字必须来自模拟结果，不允许 LLM 自行计算
- [ ] 解释包含：推荐理由、主要风险来源、一个反事实对比（"如果选 X，最坏情况下……"）

### F5 事件注入与预警（P1）

回放预设事件（关税上调、供应商延期），状态模型更新后自动重算，并对受影响的在途订单发出预警。

- [ ] 预警说明受影响订单、新增成本或现金缺口，以及建议的下一步
- [ ] 事件可以在 Demo 中通过按钮触发

### F6 供应商谈判模拟（P1）

LLM agent 扮演工厂，根据其设定的底线和偏好，对用户提出的预付比例、订货量、价格组合做出回应。

- [ ] 工厂 agent 的底线参数预先设定，不会超出底线让步
- [ ] 每轮谈判后，用模拟器展示新条款对现金流的影响

## 模拟引擎规格

引擎按天推进，默认模拟 120 天、1000 条路径，固定随机种子；所有输出数字都来自这里。

**决策变量**：订货量 Q（每个方案一个值），以及可选的预付比例 α。

### 不确定性

| 变量 | 默认分布 | 来源 |
|---|---|---|
| 日需求 D_t | 从 M5 中相似 SKU 的历史序列自助抽样，按品牌规模缩放 | M5 数据 |
| 交期 L（天） | 对数正态，均值和波动由供应商设定 | 合成供应商数据 |
| 关税率 τ | 以概率 p 从当前税率跳到新税率 τ′ | 当前 HTS 税率 + F3 提取的信号 |
| 供应商违约 | 以概率 r 发生，已付预付款损失且不交货 | 供应商风险评分 |

**付款时点**：下单时付 αQc；出货时付 (1−α)Qc；到港时付关税 τQc 和运费 Qf。其中 c 为单位采购成本，f 为单位运费。

### 库存与现金的每日更新

$$S_t = \min(D_t,\ I_{t-1}), \qquad I_t = I_{t-1} - S_t + Q \cdot \mathbb{1}[t = L]$$

$$C_t = C_{t-1} + (P - m)\,S_t - F - \text{Pay}_t$$

其中 S_t 为实际销量，I_t 为库存，C_t 为现金，P 为售价，m 为单位平台和履约费用，F 为每日固定成本，Pay_t 为当天发生的采购相关付款。现金低于 0 时先动用授信，授信用尽视为现金断裂。

### 输出指标（每个方案）

| 指标 | 定义 |
|---|---|
| 现金跑道 | 现金首次低于安全线的天数；未触及则记为大于 120 天；报告 P10、P50、P90 |
| 断货概率 | 至少有一天需求未被满足的路径占比 |
| 预期利润 | 120 天内累计毛利减采购、关税、运费的均值 |
| 最坏情况损失 | 利润分布的第 5 百分位 |
| 现金扇形图 | 每天现金余额的 P10、P50、P90 |

**优化**：在用户给定的方案之外，引擎可在 Q 的合理范围内做网格搜索，作为"系统建议订货量"补充展示。

## 数据模型

MVP 共 7 个核心实体，结构按 ontology 方式组织，便于后续迁移到 Luvio 的 PostgreSQL 多租户架构。

| 实体 | 关键字段 | 说明 |
|---|---|---|
| Brand | id、名称、现金余额、授信额度、现金安全线、每日固定成本 | 一个租户对应一个品牌 |
| SKU | id、名称、售价、单位平台费用、当前库存、HTS 编码、需求模板 | 需求模板指向 M5 中的参考序列 |
| Supplier | id、名称、国家、交期均值与波动、最低订货量、默认预付比例、风险评分（0–1） | 风险评分映射为违约概率 r |
| SupplierOffer | SKU、Supplier、单位成本、单位运费 | 同一 SKU 可有多个供应商报价 |
| PurchaseOrder | id、SKU、Supplier、数量、预付比例、下单日、状态（计划中/在途/已到港） | 在途订单参与模拟 |
| Scenario | id、关联采购单、方案列表（订货量、预付比例）、随机种子、模拟结果 | 一次比较即一个 Scenario |
| RiskSignal | id、原文、引用句、影响对象、参数名、变化值、概率、状态（待确认/已接受/已拒绝） | 只有"已接受"的信号会进入模拟 |

## 界面需求

MVP 共 4 个页面，Demo 主要停留在"决策工作台"。

| 页面 | 主要元素 | 对应功能 |
|---|---|---|
| 品牌概览 | 现金余额与授信、SKU 库存表、供应商卡片（含风险评分）、在途订单列表 | F1、F5 预警入口 |
| 决策工作台 | 方案输入区（订货量、预付比例）；三列结果卡（跑道 P10/P50/P90、断货概率、预期利润、最坏损失）；现金扇形图与安全线；推荐方案高亮与解释文字 | F2、F4 |
| 风险信号 | 文本输入框；提取结果列表（参数变化 + 高亮引用）；接受/修改/拒绝按钮 | F3 |
| 谈判室（P1） | 对话窗口；当前条款摘要；条款变化后的现金曲线对比 | F6 |

### 交互要求

- 参数变化后，结果区显示"已过期"标记，点击重新运行，避免用户误读旧结果
- 推荐方案与用户选择不一致时，叠加展示两条中位数现金曲线
- Demo 模式下提供"注入事件"按钮和评委投票入口

## 非功能需求

最重要的两条是可复现和数字可追溯：同样的输入必须得到同样的结果，界面上每个数字都能追溯到引擎。

| 类别 | 要求 |
|---|---|
| 可复现性 | 固定随机种子；相同输入的模拟结果逐位一致 |
| 数字可追溯 | LLM 生成的文字中出现的数字，必须与引擎输出逐一匹配；不匹配时不展示该段解释 |
| 延迟 | 3 个方案 × 1000 条路径的模拟在 2 秒内完成；LLM 解释在 5 秒内返回，期间先展示数字结果 |
| 可解释性 | 每个推荐都附带主要风险来源和至少一个反事实对比 |
| 稳健性 | LLM 调用失败时，模拟器和图表仍可独立使用；Demo 准备离线录屏作为备份 |
| 数据安全 | MVP 只使用公开数据和合成数据；赛后接入真实数据时按租户隔离 |

## 成功指标与发布范围

Hackathon 版本以 Demo 闭环跑通为准；赛后版本以真实用户是否据此改变采购决策为准。

| 版本 | 范围 | 成功指标 |
|---|---|---|
| Hackathon MVP | F1–F4 必做，F5–F6 尽量做；虚构品牌 + 公开数据 | 三个 Demo 决策点端到端无故障；评委能在 30 秒内看懂推荐理由 |
| 赛后 Alpha | 接入 1–3 家真实品牌的手工导入数据；补齐 F5、F6 | 用户在至少一次采购中参考推荐；用户认为解释可信 |
| Beta | ERP 和电商平台数据接入；作为 Luvio 模块上线 | 每周活跃使用；用户愿意为此付费 |

Alpha 阶段的具体指标数值待与首批用户访谈后确定。

## 开放问题

- [ ] 现金安全线如何设定：由用户输入固定金额，还是按"N 天固定成本"自动计算？
- [ ] 供应商风险评分如何映射为违约概率 r，MVP 先用什么规则？
- [ ] 需求模板如何从 M5 中为虚构 SKU 挑选参考序列，是否需要按品类匹配？
- [ ] 关税信号的发生概率 p 由 LLM 估计还是由用户指定？倾向于由用户指定，LLM 只给出参考
- [ ] 模拟周期 120 天是否足够覆盖海运交期加销售周期？
- [ ] 赛后真实品牌的数据最少需要哪些字段，导入成本是否可接受？
